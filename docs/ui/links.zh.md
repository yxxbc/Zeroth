# 可点击链接 —— 给被换行的 URL 用的 OSC 8 超链接

本页讲 URL 那一半。散文与 tool 输出里可点击的**文件路径**、链接**预览卡片**、
以及点击展开，另有单独的设计，连同它们引出的屏幕归属取舍：
[`rich-links.md`](rich-links.md)。

## 那个 bug

一个比本行剩余空间更宽的 URL，会硬换行跨过多个显示行 —— `wrap_inline` 的
grapheme 硬断，对一个任何行都装不下的词来说这是正确的*视觉*行为（窄终端、表格
单元格的一列、深列表缩进）：

```
  the credit lives at https://github.com/linuz
  tx. That is the loop …
```

让那段文本可点击的是终端自己的 URL 检测，而它是按**可见的行文本**工作的：它在一
行上看到 `https://github.com/linuz`，在下一行上看到一个无关的 `tx.`，于是点击
打开的是那个被截断的 URL。没有任何换行策略能修好这一点 —— 一个比内容宽度更宽的
URL *必须*在视觉上被切开 —— 所以修法只能把点击目标与视觉换行解绑。

## 修法：显式的 OSC 8 超链接

[OSC 8](https://gist.github.com/egmontkob/eb114294efbcd5adb1944c9f3cb5feda)
（`ESC ] 8 ; params ; URI ST`）把一整个目标 URI 附着在它开着期间打印的任何单元格
上，与文本坐在哪里、在哪儿换行无关。一个被检测到的 URL 的每一个渲染片段都被这对
序列括起来，于是点**任何**片段都打开**整个** URL。支持它的终端（kitty、iTerm2、
WezTerm、Ghostty、foot、VTE、Windows Terminal、tmux ≥ 3.4）还会经 `id=` 参数把
各个片段作为一个链接一起悬停下划线；不支持的终端只是把这串序列吞掉（ECMA-48
OSC），于是屏幕逐字节仍是原样 —— 换行、样式，以及那套旧的自动检测行为在那里全不
受影响。

Markdown 链接白得同样的待遇：`[text](url)` 依旧渲染成 `text (url)`，但文本与显示
出来的 URL 现在都带着真正的目标。

### 装饰用的括号

那个显示出来的目标两侧的 ` (` 与 `)` 是**这个渲染器加的装饰** —— 它们既不在源行里
也不在 URL 里 —— 所以它们穿周围散文的装束，不携带任何目标。它们过去会拿走链接
自己的蓝 + 下划线，读起来像一个连续链接一直延伸到收尾括号，而一次点击（只有*被
标记*的那一段才携带）却在不带它们的情况下打开 URL：这就是所报告的 bug。把它们交
还给散文，也正是让形状一致的原因 —— 一个散文碰巧用括号括起来的裸 URL
（`(see https://x.com/y)`）向来是那样读的，因为 `find_urls` 会按它的「不配对收尾
符」规则把 `)` 交还，而一个 `● Read({path})` 头部的括号也始终是朴素的。

所以 `` [`AGENTS.md`](AGENTS.md) `` 显示为 `AGENTS.md (AGENTS.md)`：标签用行内
代码的颜色，显示出来的目标用链接蓝 + 下划线，括号（以及整件事外面的任何引号）用
回复自己的散文颜色，而携带那个逐字 `AGENTS.md` 目标的正好是那两个名字。一个相对
目标按它的原样搭乘 OSC 8 转义 —— 只有文件 tool 头部把路径解析成绝对的 `file://`
URI（`links::file_url`），因为只有它被交给 session 的 cwd 策略。

## 文件路径

`links::find_paths` 在 assistant 散文与行内代码里检测形似路径的 token：一个以
空白分隔的、以 `/`、`./`、`../` 或 `~/` 开头的词，或一个含 `/` 且最后一段非空
的词（`src/app/tools.rs`）。尾随的 `:line[:col]` 被排除在目标之外，仍是纯散文；
glob（`src/*.rs`）、flag、`key=value` token、反斜杠与 URL（`://`）一律拒绝。检测
是词法的 —— 它从不碰文件系统，所以一个不存在的路径依然会被链接，由打开器报出来。

渲染器把每个片段经 session 的 `PathDisplay::file_url` 解析：目标是该文件绝对的、
百分号编码的 `file://` URI，`~` 与相对路径按 session 的 cwd 解析。一个没有绝对
cwd 的相对路径（逐字策略、一个单元测试）保持朴素。散文里的路径拿到与 URL 相同的
链接装束与载体；行内代码保住它的字面颜色，只多拿到载体。一个在流式行尾仍在生长的
路径，由 `has_forming_path` 扣住，那是 URL 规则（`links::has_forming_url`）的
孪生。

tool **输出**仍不被链接（它的按词换行与截断是另一套）；tool 头部自己的路径被
链接，assistant 散文与代码也是这样。

## 各部分住在哪里

完整的 URL 只在被换行切开**之前**才是已知的，而转义只能在终端**处**写出 —— 所以
这个设计把链接身份从渲染器穿到绘制边界，走的是那一条能活过这趟旅程的逐单元格
通道。

1. **`src/links.rs` —— 纯核心**（`markdown` 模块的孪生）：
   - `find_urls` 在一个文本节点里检测裸的 `http://`/`https://` URL：scheme 必须
     在一个非字母数字边界上开启，主体收下所有可打印而不属于空白/`<`/`>`/`"`/`` ` ``
     /`|` 的字符，尾部则修剪掉收尾标点（`.,;:!?'"`）以及*不配对的*收尾符
     （`)`/`]`/`}` —— `…/Foo_(bar)` 保住它的 `)`，一个在 `(see …)` 里的 URL 则把
     它交还）。控制字符（被偷运进模型输出的一个 `ESC`）终止 URL —— 它们绝不可能
     进入一个目标。
   - `is_whole_url` 回答另一个问题：一段文本是否整段、*就是*一个 URL —— scheme
     在它的第一个字节、而且里面没有任何 URL 装不下的东西（同一条主体规则：没有
     空白、控制字符或 `<>"`` ` ``|`）？这样的文本**逐字**被链接，因为上面那套尾部
     修剪是散文的规则 —— 一个句子拥有它收尾的 `.`，一个插入语拥有它的 `)` ——
     而一段*就是* URL 的文本没有散文可以交还任何东西。只有 `http://`/
     `https://` 合格，所以没有别的 scheme 会以这种方式变成目标。
   - 一个进程级、只追加的 **URL interner**（`highlight` 的语法单例先例：一个渲染
     层缓存，不是 app 状态）把每个 URL 映射到一个稳定的 24 位 id，并可反查。
   - **载体**：`linked(style, url)` 把这个 id 以
     `Color::Rgb(id>>16, id>>8, id)` 盖进 `Style::underline_color`。crate 里没有
     别的东西设置下划线颜色，id `0`（纯黑）被保留为「不是链接」，而其他每一种颜色
     类别都解码为 `None` —— 所以这条通道是无歧义的。载体活过 `Span` →
     `Cell::set_style`、`Buffer::diff`、transcript 缓存，以及一次 reflow 的重绘
     （interner 给同一个 URL 同一个 id），而绘制边界在终端见到它之前就把它剥掉，
     所以不会有杂散的 `SGR 58` 下划线颜色泄漏出去。
   - **成帧**：`osc8_open(id, url)` / `OSC8_CLOSE` 造出这串转义，把终端可能误解析
     的每个字节（控制字符、空格、DEL、非 ASCII —— kitty 规范的规则）做百分号编码，
     作为纵深防御式的转义注入防护。
2. **`src/ui/inline.rs` —— 标记。** `inline_spans` 是所有 assistant 散文都会经过的
   唯一漏斗（纯文本行、列表项、引用块，*以及*表格单元格），所以在那里标记就覆盖了
   每一个可能换行一个 URL 的表面：
   - `Inline::Text` 的自动链接：URL 片段拿到 markdown-URL 的装束（`link_url_color()`
     + 下划线 —— 一个 URL 就是一个 URL）加上载体。
   - `Inline::Link { text, url }` 给文本各 span 打上目标（它们可见的样式不变），
     也给 ` (url)` 后缀里的那个 `url` 打上。
   - `Inline::Code` 也标记裸 URL，但保住它的字面文本与代码颜色 —— 不覆盖成
     蓝/下划线。此前，把一个长的 token URL 放进反引号会悄悄绕过 OSC 8：只有第一个
     换行出来的行被自动检测到，点击时丢掉这个 token 的其余部分。
   - `linkify_code_segments` 给已经上好样式、**未换行**的代码附上目标，不改变它的
     字节或可见样式。它扫描整条源行，再把 URL 的字节范围与它的样式 span 求交，于是
     把一个 scheme、路径或查询拆开的语法高亮，仍让每一片拿到同样的完整目标。代码
     检测（`links::find_code_urls`）尊重一个开启的引号，于是 `').json()` 以及相邻
     的带引号字符串绝不会被吞进目标。一个带引号的 URL 或一个开启代码字面量的 URL
     原样保住尾部标点（`?token=abc!` 包含 `!`）；这个决定只取决于 URL 之前的文本，
     所以之后流来的代码无法改变一个已提交的目标。源字符串里的转义与插值不求值。
     `AssistantRenderer` 在 `code_content_rows` 之前标记代码；代码的间距与语法颜色
     保持完好。不同的源行绝不会被拼成一个猜出来的 URL。
   - **标题**的文本是像散文一样的 inline markdown（`docs/ui/markdown.md`
     *Headings*），所以其中裸 URL 经 `inline_spans`、在标题的修饰之下，拿到散文的
     装束与载体；相邻的等样式标题 span 会被合并，好让组合用附加符号留在它前面的
     字形上。一个**自动链接**（`<https://…>`）是 `Inline::Url`：它那个裸 URL（尖
     括号被去掉）穿链接装束，携带它的目标（一个邮箱地址则是 `mailto:`）。
   - 非 markdown 角色（用户/系统/shell 文本）与 tool 输出仍依赖终端对未换行 URL 的
     检测。
3. **`src/ui/model_view.rs` —— picker 家族的标记。** assistant 散文不是唯一显示 URL
   的地方：`/login` 的各登录页会打印一个用户理应去*操作*的 URL。
   `model_linked_rows` 是 `model_wrapped_rows` 的链接孪生 —— 它在**未换行**的文本
   里标出那些 URL，再经 `inline::wrap_inline` 换行，于是载体像在散文里一样活过硬
   断。它与散文漏斗刻意为了一点不同：它保住**调用方的颜色**，只加下划线，因为这些
   页面刻意点亮它的 URL（设备码页把它调暗，好让框里的设备码仍是眼睛落下去的地方
   —— `docs/providers/copilot.md`），而聊天的链接装束会推翻这一点。浏览器登录页
   于是完全不需要在 URL 前面加一个动词（`docs/providers/chatgpt.md`）：链接本身就是
   可供性。

   `/mcp` manager 的登录流程（`docs/tools/mcp.md`）也显示 URL，过去把它们当作朴素
   的行打印 —— 于是它 **Authenticate** 页的授权 URL（几百个字符宽、总是被硬断）被
   点击时只打开它第一行的片段，下面那些行则什么都不打开，而在 `/login` 页上同样的
   点击却有效：这就是所报告的 bug。它现在走这个家族的 builder，一共三个：
   - `model_url_rows` 用于一段**就是**一个 URL 的文本（`links::is_whole_url`）：
     `model_linked_rows` 的装束，但整个文本就是目标，逐字（`whole_url_run`）。
     授权 URL 是这页唯一显示的东西，也是 `c` 复制、交给浏览器的那个 URL，所以点击
     必须打开恰好它 —— 哪怕它结尾在一个 `.` 或一个不配对的 `)` 上，而散文检测会把
     它们交还给一个并不存在的句子。它保住页面一直点亮它的那个强调色，带下划线。
   - `whole_url_run` 用在**服务器页的 `URL:` 行**上，那行在它的标签之下换行
     （`field_rows` 把换行后的 span 摆出来，于是这行读起来与从前完全一样）；一个
     stdio 服务器的 `Command:` 行不是地址，保持朴素，任何不是整段一个 URL 的值也
     一样。
   - `model_linked_rows` 用于这个流程显示的两条**理由** —— 一次被登录拒掉的粘贴
     （一个授权服务器的 `error_uri`）、以及一个连接失败的服务器（一个用来启用 API
     的控制台）：散文里的 URL 被链接，理由自己的颜色保住，即 `/login` 失败信息那
     条规则。

   tool 页面由服务器写入的文本（一个描述、一个参数的说明）不被链接，这是 *限制*
   里那条给 tool 输出的规则。
4. **`src/term.rs` —— 发射。** 四条写单元格的路径 —— scrollback 提交 + reflow
   （`draw_lines`）、live 区域的整块 blit、live 区域的 diff、以及备用屏 overlay
   （`draw_overlay`）—— 本就都汇入 `Backend::draw`；它们现在经过一个 `draw_cells`
   收窄点，后者把连续的单元格按载体 id 分组，未标记的连续段原样传过去（零拷贝），
   并用 `osc8_open` … 剥掉载体的单元格 … `OSC8_CLOSE` 把每一段被标记的包起来。
   覆盖*所有*路径，正是让链接在一个单元格可能被绘制的每个地方都活着的原因（一条
   已提交的消息、一次 resize 重建、流式条带、Ctrl+O transcript），也正是让载体
   绝不作为一个真正的下划线颜色抵达终端的原因。超链接在每个终端里都是按被打印的
   单元格算的，所以一次重绘 URL 一半的 diff 恰好重新链接那些单元格，其余的保住
   自己的。
5. **`src/ui/tool.rs` —— 文件 tool 的头部。** 一个
   `● Read/Write/Edit({path})` 头部的路径是一个指向**文件**的链接：
   `tool_header_lines` 用 `links::file_url` 给路径的各 span 打上 —— 该文件
   *绝对的* `file://` URI（一个相对参数经 `app::PathDisplay::file_url` 按 session
   的 cwd 解析，`.`/`..` 折叠，`/` 与 `A-Za-z0-9-._~` 之外的每个字节做百分号编码，
   即 `Path.as_uri()` 的规则，于是一个名字里的空格或 `#` 绝不可能读成一个分隔符）
   —— 无论这一行画的是哪种短形式（`cat_poem.txt`、`~/hello.py`、`/tmp/x.py`；
   `docs/tools/tools.md` *Path display*）。目标是在头部换行**之前**打上的，所以
   一个被硬断跨过续行的长路径、或被裁到折叠头部列预算的路径，从任何片段点开都是
   整个文件。**只有路径**：框住它的 `(`/`)`、圆点与名字保持朴素，而它下面那些
   `⎿ Wrote 21 lines to cat_poem.txt` / `⎿ Updated cat_poem.txt (+4 -4)` /
   `⎿ Read image (PNG, …)` 角行从不被链接 —— 头部说的是*哪个*文件，也是点击应当
   打开的那一行。可见文本与样式逐字节相同（链接穿参数自己的粗体白；支持它的终端
   会悬停下划线），一个 `Bash`/`Agent`/MCP 头部不携带任何东西，而一个策略放不下
   的路径 —— 一个没有 cwd 的相对参数，逐字策略唯一的缺口 —— 照旧绘制，不被链接。
   共享这个头部 builder 的每个表面都以同样方式链接：inline 单元格、live 条带的
   运行中单元格（一个在 permission gate 上等待的 `Write`）、Ctrl+O transcript，
   以及一个 subagent 会话视图。

`ZEROTH_HYPERLINKS` 给它把关（默认**开**；一个假值 —— `0`、`false`、`no` —— 为
一个行为乖张的终端关掉发射，即 `ZEROTH_DISABLE_KEYBOARD_ENHANCEMENT` 那套模式）。
这个闸门在 `InlineViewport::init` 时读一次；被禁用时仍然剥掉载体 —— 那个 id 绝不
许被当成颜色画出来 —— 只是不写任何 OSC。

## 守住了哪些不变量

- **转义是隐形的；装束是有范围的。** 在每个终端上，换行与行文本都与从前逐字节
  相同 —— 唯一新增的字节是终端渲染为空无的 OSC 序列，没有一个字符移动。两处刻意
  的装束改动，方向相同：裸 URL 拿到了一个 ` (url)` 目标一贯就有的链接蓝 + 下划线，
  而一个 markdown 目标的装饰括号把那份装束交还出去 —— 于是眼睛读作链接的那一段与
  点击所打开的那一段，在每一处都是同一段。
- **前缀稳定性不受影响**（不变量 2）：标记发生在一行自己的渲染之内 —— `find_urls`
  从不跨行看 —— 所以一条已完成的行，它的各行仍然从不改变。条带对一个*部分* URL 的
  预览链的是那个部分（它随其生长 intern 几个短命的 id —— 有界、字节上便宜）；已
  提交的行链的是整件事。在**仍然在长**的尾行之内，检测是追溯性的 —— `ht` 在足够
  多的 `http://…` 到达、足以重设整个词的样式之前只是纯散文，而一个主体抵达行尾的
  URL 会继续生长（被修剪的尾部标点会重新接回：`http://e.` → `http://e.com`）——
  所以 `links::has_forming_url` 报告这两种形状，而 `StreamRender::commit` 在其中
  之一成立时扣住这一行（`markdown::has_open_inline` 那套模式；一个压力模糊测试的
  发现 —— 一个纯样式的 `h` 行在窄宽度下提交之后曾被重绘成蓝+下划线）。一个已被
  停用符封住的 URL、以及一个 scheme 边界规则永不会链接的词中片段，则保持已定，并
  逐段提交。
- **三个 `mod.rs` facade 不动**：`links` 是一个新的顶层纯模块（像 `markdown`），
  可被 `ui` 与 `term` 取用，而不放宽 `tests/api_surface.rs` 锁住的 `ui` 表面。

## 测试

纯核心（检测、interner、载体往返、成帧/编码、连续段分组、环境谓词）在 `links.rs`
里做单元测试；标记，以及
*被换行的片段仍然携带整个 URL* 这个回归，在 `ui` 里做单元测试。一个合成的
token URL 在若干窄宽度下被渲染进纯散文、行内代码、围栏/高亮与缩进代码、标题、
列表、引用和表格。测试还会把 URL 切跨每一个可能的语法样式边界、保住 Unicode 与
间距，并把每一个流式前缀（含载体）与批量渲染对比，好让任何部分目标都不会提交。
引号界定的代码 URL、以标点结尾的字面量、只重绘载体的 diff、以及被绘制的标题里的
组合用附加符号，都有显式的回归。装饰括号也两半都有 —— 各段自己的装束在
`ui/tests/inline.rs`，以及整个 `` "[`AGENTS.md`](AGENTS.md)" `` 经
`message_lines` 的渲染在 `ui/tests/assistant.rs`，各自跨若干宽度，因为换行会按样式
重新合并一行的 span，而一个保住了链接装束的括号会回来成为它自己那个带下划线的

## 限制

- OSC 8 支持必须在终端以及它与 app 之间的任何 multiplexer 里启用。如果这些序列
  被禁用或丢弃，终端按行的普通自动检测恢复不了一个被换行的 URL。app 的默认闸门是
  开的；请检查 `ZEROTH_HYPERLINKS` 不是假值。
- 源 URL 里一个真正的换行不是一次视觉换行：不同的源行保持各自独立，而不是去猜该
  不该把它们拼接。
- 没有 scheme 的 `www.…` 文本不被链接（OSC 8 需要一个真正的 URI；编造一个 scheme
  就是瞎猜）。
- tool/shell 输出暂不被链接 —— 它的换行（`wrap_output`）在词边界断开，所以那里
  的 URL 只有宽过终端才会被切开；同一个载体若证明值得，可以在那里扩展。assistant
  散文与行内代码链接 URL**和文件路径**；文件 tool 的**头部**是唯一被链接的 tool
  表面（链到文件，而不是文本里的某个 URL），而它下面的 `⎿` 角行刻意保持朴素。
- `file://` 目标按 session 看到的样子命名文件：一个相对参数按词法对进程 cwd 解析，
  从不查询符号链接，而一个从别的目录 `/resume` 出来的 session，链接的是头部现在
  所读的地方（与显示出来的路径同一条规则）。一次点击拿到一个 `file://` URI 之后
  *做什么*是终端的选择 —— kitty、Ghostty、WezTerm 与 iTerm2 交给系统打开器，
  VS Code 的终端在编辑器里打开它。
