# 凭据生命周期：刷新、恢复与退出

日期：2026-11-14

## 决策

保留 `/login` 作为连接入口，在一级菜单增加 **Manage connections / sign out**，
并让 `/logout` 打开同一个可搜索页面。页面列出已登录账户和已配置 API key，
包括从环境变量继承的 key。选中一行后需要确认，区分 **Sign out** 与
**Remove API key**。这里执行本地断开连接，不在服务商侧撤销 token。

退出会删除所选连接保存的凭据（包括旧名称别名），清除认证缓存，停止使用该连接的
工作，并持久保存禁用标记。该标记优先于环境变量和通用 key 回退，重启后依然有效，
并防止进行中的刷新恢复已删除的凭据。重新登录保存新凭据时会清除标记。
不会改写父 shell 的配置。

## 刷新事务

所有凭据存储修改都在独立、稳定的锁文件上获取有超时的跨进程建议锁。
存储文件的原子替换不会替换锁。轮换凭据的 provider 还会在读取最新 refresh token、
交换及持久化的整个过程持有逐凭据锁。因此，内存配置过期的进程也会使用另一个
进程最近保存的 token。获取锁失败会拒绝刷新，不会退回到重放旧 token。

退出只获取短时间的存储修改锁，不等待覆盖网络请求的刷新锁。刷新写入要求连接
依然启用，且存储中的凭据依然属于本次刷新的轮换链。持久化失败会显示通知，
不输出任何凭据；当前轮换仍保留在内存里，让当前进程可以继续工作。

## 未授权恢复

OAuth 推理请求在输出任何响应内容之前被 HTTP 401 拒绝时，可以清除缓存的
access token 并刷新一次。第二次 401 直接失败。API key、403 响应、被撤销、
无效或重复使用的 refresh token，以及已输出流式内容后的失败都不进入该恢复路径。
不会因此重新执行工具。

## 验证

离线测试覆盖真实进程互斥、旧配置读取最新轮换、刷新过程中退出、禁用环境变量回退、
凭据文件完整性和有界的 401 恢复。通过真实二进制与本地冒烟模拟服务验证两个退出入口、
账户退出及 API key 移除，不需要真实凭据。长时间在线验证仍需主动选择，且不能为
服务商的非官方或无版本接口建立服务级保证。
